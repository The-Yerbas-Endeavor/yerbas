Experimental static Qt build
===========================
Status: Linux Qt compilation and end-to-end wallet validation are still pending.
This is opt-in groundwork, not a validated three-executable release package.
The default GitHub Actions builds continue to use shared Qt packaging.
Windows static dependency builds and packaging are not yet implemented; macOS
continues to use its app bundle.

From a clean source checkout with the native Qt build dependencies installed:

  python3 ci/build-native-qt.py --prefix "$PWD/qt-static" --cmake cmake --static
  python3 ci/static-qt-link.py --prefix "$PWD/qt-static" --output "$PWD/qt-static-link"
  export PKG_CONFIG_PATH="$PWD/qt-static/lib/pkgconfig"
  export QT_STATIC_LIBS="$(cat qt-static-link/wallet.libs)"
  export QT_STATIC_TEST_LIBS="$(cat qt-static-link/wallet_test.libs)"

Run autogen.sh, configure, and make with the usual wallet dependencies and
--with-gui=qt6 --with-qtdbus=no --enable-tests. Keep qt-static-link until linking
has finished: its Qt-generated plugin initializer objects are part of the link.
Use build paths without spaces. The helper rejects shared Qt and fails if its
probe executables cannot link. It does not replace runtime tests.

Before changing release packaging, validate the actual executables in a clean
runtime environment, including GUI startup, minimal-platform Qt tests, image
plugins and TLS. Verify there are no external Qt library dependencies or missing
libraries. Static Qt does not mean the Linux executable is fully static: system
C/C++ and desktop libraries can still be required. Preserve applicable license
notices and redistribution materials separately from the three-binary folder.
