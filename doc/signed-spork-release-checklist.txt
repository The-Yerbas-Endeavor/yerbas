Signed LOW_LLMQ release candidate — operator and rollout notes

Scope
This candidate retains existing LOW_LLMQ parameters and PoSe cleanup. It adds
fee-paying, authority-signed manual ON/OFF transactions and a cutover selected by the first signed ON
transaction. It does not change collateral, renew registrations, expire ON after a
fixed duration, or exclude older peer versions automatically. PoSe banning is
not deletion of the collateral registration. Normal profile sizing still counts
all registrations, including banned ones. Ensure enough live operators for the
normal minimum before sending OFF; cleanup alone does not lower that minimum.

Activation
The first mined, authorized ON transaction selects the cutover; no mainnet
activation height is assigned in a release. Software support is enabled by the
network policy fLLMQRecoveryByRecord. This is not itself LOW_LLMQ activation.
The first effective boundary aligns all quorum schedules (every 720 blocks).
The RPC schedules it 30 to 749 blocks ahead. Later ON/OFF uses 30-block rounds.
Upgraded nodes must be installed before submitting the first record.

At the cutover
Existing registrations, balances and PoSe state are retained. Recorded recovery
starts ON at the first record's effective height. Pre-cutover quorums cannot sign for post-cutover signing heights;
historical commitments remain valid data. Quorum services can pause until new
quorums form, but PoW blocks and recovery transactions do not need a quorum.

Commands after activation
Configure the existing authorized sporkkey securely and fund/unlock the wallet
for ordinary transaction fees. Use:
  quorum recovery status
  quorum recovery on
  quorum recovery off
The result identifies the transaction, fee, effective height, and last inclusion
height. Broadcast is not confirmation or activation. ON has no automatic expiry.
An unmined request past its inclusion deadline must be recreated. Fee payment
alone grants no authority. Only one pending recovery transaction is admitted;
expired and branch-invalid requests are removed from the mempool. This request
deadline does not turn off an already active ON authorization. Expired or
branch-stale requests relayed by peers are rejected without a ban penalty.
Do not use the legacy gossip spork command to activate recorded LOW_LLMQ;
it does not create a transaction.

History and upgrades
Before the first record's effective height, mainnet retains the legacy exact-size
null-commitment check, hard-coded historical LOW_LLMQ windows, and established
legacy spork setting. The broad legacy null-size replay accommodation is not
used on mainnet. Historical windows already encoded in chainparams are preserved;
this does not reconstruct any additional unrecorded spork transitions.
Above activation, the chain records determine recovery history. Do not change
the legacy spork setting as part of a recorded transition.
Upgrade before the first transaction. Existing unpruned nodes automatically
index pre-record history from validated local blocks without rebuilding chainstate.
The scan verifies block hashes and Merkle roots, preserves wallet/UTXO/smartnode
state, and resumes interrupted batches. Already indexed nodes skip the scan.
If signed records already exist but their index is missing, use
-reindex-chainstate or -reindex. Missing/damaged historical blocks must be restored
or downloaded again; pruned nodes may therefore need a resync. Never clear just
the recovery state and assume OFF. A fresh node reconstructs it from blocks.

Authority and rollout
Use the release's configured spork address set and signature threshold. The RPC
currently signs with one configured key; a multi-authority policy would need
signature collection before it could be deployed. Authority rotation must retain
historical verification rules and is not implemented by replacing old addresses.
Protocol 70224 remains advertised. Compatible nodes must be upgraded before
activation; merely connecting to older peers does not make their validation
compatible. Do not submit the first mainnet record before successful testnet validation
and a coordinated rollout.

Acceptance
The local tests cover signed ON/OFF, exact effective boundaries, fresh sync,
reindex, rollback, preserved registrations, real DKG/PoSe, legacy quorum
retirement, and late-upgrade recovery. Cross-platform CI and testnet results must
be recorded separately; local passes are not a mainnet deployment approval.

V4 wallet asset activation safeguard
Mainnet asset creation and sending unlock at tip height 1,195,400. This is
estimated to be near 2027-01-01 00:00 UTC from explorer block 1,149,666 at
2026-10-28 03:20:02 UTC and the preceding 10,080 blocks averaging 122.5578 seconds.
It is a fixed block height, not a clock-time guarantee (nominal 120-second
spacing instead projects height 1,196,366). Recheck the estimate before release.
Qt, issuance/transfer/reissue RPCs, asset builders, and wallet commit enforce it.
This includes asset ownership transfers, reissuance and asset reward payouts.
Ordinary YERB payments and testnet/regtest asset use remain enabled. Receiving,
viewing and validating assets are unchanged. A rollback below the height relocks.
This v4 wallet policy does not change consensus, affect old binaries, or prevent
older/custom clients and raw tools from submitting transactions. A protocol
version advertisement alone does not disable older wallets' asset issuance.
