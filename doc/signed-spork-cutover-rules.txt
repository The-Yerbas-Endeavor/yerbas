Signed LOW_LLMQ cutover rules — implementation specification
Status: release-policy routing is implemented locally; public activation remains
unassigned (-1). Regtest can exercise that same policy with a 720-block-aligned
cutover override. This is not a claim that mainnet deployment is ready.

1. Release constants and scope
A is a network-specific activation height. Select it only after legacy replay
and operator rollout; no runtime setting may change A on public networks.
A must align with every affected DKG schedule so no legacy round starts before
A and expects a commitment under newly chosen parameters. Use the actual profile
intervals, including non-type-1 consumers; do not assume alignment to 30 alone.
The authority set and signature threshold are consensus rules. A normal
sporkaddr setting must not override them on public networks. Preserve protocol
70224 advertising; peer-version exclusion is a separate rollout decision.

2. Legacy prefix
Blocks below A retain the existing legacy validation path, including its null
commitment compatibility and historical quorum/PoSe boundary rules. This upgrade
does not reconstruct missing old gossip-spork history or waive signature, payment,
collateral, membership or state-root validation. Keep the established legacy
spork setting during migration; recorded ON/OFF transactions do not modify it.
The legacy path's dependence on that setting is an inherited limitation, not a
property repaired by this cutover. Verify fresh sync with the deployment setting.
Record transactions are invalid before A. Replaying the prefix must neither
create recorded authorization history nor reset registrations or penalties.

3. Bootstrap without a functioning quorum
The virtual recorded authorization state at the parent of A is OFF, with no
previous record. Preserve all reconstructed smartnode/UTXO/PoSe state.
Initialization is permitted only after the legacy prefix is valid under rule 2.
No DKG, ChainLock or InstantSend success is required to include an ON record;
ordinary mined blocks and standard transaction funding are sufficient.
The state database must distinguish a valid preactivation bootstrap from missing
postactivation records. A missing postactivation parent state is an error, never
an instruction to reset OFF. Reindex reconstructs the state from blocks.

4. Accepted records after A
Accept manual record version 2 only; reject the old bounded-window version 1.
Use the existing network/ancestor/previous-authorization/signature verification.
Require anchor height >= A-1, within the allowed recent-ancestor interval.
ON has endHeight=0; OFF has endHeight=startHeight. No automatic ON expiry.
At most one transition per block; reject a second pending effective transition,
redundant actions, wrong authority, wrong branch/network and stale predecessor.
The funding transaction pays normal fees. Paying the fee grants no authority.
A failed transaction or an unmined request changes no consensus state.

5. Inclusion and effective heights
For a record included at I, its effective height E must satisfy E>I and be an
approved type-1 quorum boundary within the configured scheduling horizon.
The RPC currently chooses the second upcoming boundary to allow inclusion time.
Its final permissible inclusion height is E-1. Missing that height requires a
new request; do not silently move a signed effective height.
At E-1 the old mode applies; at E the new mode applies. Apply PoSe decay using
the candidate block height and its parent's confirmed recovery state. A record
inside that block cannot retroactively affect the block's own decay or selection.

6. Quorum context and retirement
Resolve parameter profiles from the quorum-start parent and the authorized mode
for that quorum height. Define membership using Yerbas's established quorum-block
list unless an explicit consensus change chooses otherwise. Do not conflate the
parameter snapshot and membership snapshot. Store/pass owned profile values.
The isolated recorded-history path now resolves all three adaptive types from
owned templates and the smartnode count at the quorum-start parent. LOW changes
only type 1. Types 2 and 3 retain their 360/720-block schedules and normal count
thresholds. Fixed experimental types retain their network configuration.
This does not replace the legacy mainnet resolver: its historical update timing
and PoSe boundaries still require validation against the archived chain.
An OFF record does not invalidate an earlier commitment. Its old LOW quorum
ceases current signing eligibility at OFF; a later ON must not revive it.
If no normal replacement quorum exists, services wait rather than accept an
unauthorized weak quorum. Ordinary block production continues independently.
For the release cutover, every pre-A quorum becomes ineligible for new signing
at A. Historical commitments remain in the chain and retain normal commitment
retention accounting; the signing cutoff does not erase historical data.
Signatures evaluated for a pre-A signing height retain legacy eligibility.
New post-A quorums follow recorded rules, including manual OFF retirement.
This can interrupt quorum-dependent services until replacement quorums form;
ordinary block production and paid recovery activation remain available.

7. Reorganization and status
Recovery state belongs to block hashes and participates in the same atomic
connect/disconnect operation as other evolutionary state. Disconnecting a record
restores its parent's authorization. Disconnecting through A restores the legacy
path, not a new mutable OFF record attached to that old block. A competing branch
must derive its own record sequence. Stale mempool requests are revalidated.
RPC distinguishes broadcast, confirmed/scheduled, and effective states. Gossip
spork display is not the authoritative recorded-history status.

8. Acceptance evidence required
Replay archived mainnet blocks with assumevalid=0 and the established legacy
spork setting; check the expected block hash and state roots for compatibility.
Then exercise the release-policy cutover with fresh sync and reindex across A.
Confirm that gossip changes do not override recorded post-A authorization.
Do not claim that this makes pre-A legacy history independent of gossip. Test A-1/A/E-1/E, pre-A record
rejection, legacy-version rejection, missing database state, stalled DKG bootstrap,
second ON after OFF, old LOW signing retirement, and reorg across A and records.
Check all enabled quorum types, PoSe, payments and existing registrations. Passing
serialized archive extraction or daemon exit code alone is not consensus replay.
